# 工程护栏体检（Engineering Guardrails Audit）

中文 | **[English](README.md)**

面向 AI 编程 Agent 的元审计员 Skill：审计对象不是业务代码，而是**工程防御网本身**。通过静态扫描目标工程的基础设施、配置与构建脚本，判断 **6 大物理防御绊线**是否缺项，输出成熟度等级报告与加固建议。

技术栈无关、业务无关、不运行你的业务测试。

## 为什么需要

AI Agent 迭代代码时习惯走捷径——静默吞异常、异步错误无人处理、跨层反向调用、假绿测试。文档和口头约定拦不住它们，只有**程序化物理门禁（Exit Code ≠ 0）**才拦得住。

这个 Skill 审计的就是：这些门禁到底存不存在——以及到底会不会真的触发。

## 安装

```bash
npx skills add Tonys-L/engineering-guardrails-audit
```

支持 Claude Code、Cursor、Codex、TRAE 等 75+ Agent（[skills CLI](https://skills.sh) 生态）。

## 6 大绊线

| # | 绊线 | 防什么 |
|---|---|---|
| 1 | 语义与类型 | 严格检查退化、异步错误未处理、类型断言逃逸通道 |
| 2 | 架构拓扑 | 跨层反向依赖、循环依赖 |
| 3 | 契约同步 | 版本 SSOT、清单与实现脱节、i18n 不对称 |
| 4 | 质量防放水 | 空 catch/except、重复率阈值、覆盖率底线 |
| 5 | 环境纯净 | 冲突标记、私有绝对路径、产物体积预算 |
| 6 | 防假绿 | 往返保真测试、直连生产源码、单命令聚合门禁 |

## 成熟度等级

```
Level 0  裸奔        → 无任何程序化防护
Level 1  语法防护    → 类型绊线就位
Level 2  架构防护    → + 依赖拓扑
Level 3  契约防脱节  → + SSOT 与清单比对
Level 4  工业级      → 6 维全就位，CI 强制
```

等级由确定性公式计算（最长合格段、至多 1 个减损维）——同样的输入，任何一次运行都得到同样的结果。

## 检测的三类失真

| 失真模式 | 含义 |
|---|---|
| 虚假安全感 | 文档声称有防护，配置里实际没有 |
| 虚假指控 | 审计员报了已被修复的缺口（陈旧证据） |
| 恒真门禁 | 看似 CI 强制，失败路径在 CI 环境不可达 |

## 证据等级

每个"已布防"结论都带证据等级：`E1 CI 阻断合并 > E2 本地聚合/git 钩子 > E3 手动 > E4 仅配置 > E5 纸面无效`。

## 使用

对你的 Agent 说：

- "帮我审计一下这个工程的护栏完整不完整"
- "这个项目交给 AI 迭代会不会被改乱？"
- "评估一下工程成熟度到 Level 几了"
